# Finding correctness labels (private)

This contract prepares a private worksheet for correctness labels on every finding in one validated run. It does not fit a confidence model, choose a reporting threshold, or infer correctness from agreement among agents. Keep the manuscript, run, label packet, completed labels, and any later calibration data outside Git.

Run `python bench/calibration/labels.py prepare /absolute/private/run-1 /absolute/private/label-packet.json`. The packet contains finding IDs and hashes, without finding claims or manuscript text. Copy its `label_template` into a separate private `labels.json`. Two reviewers independently inspect each recorded finding against the original manuscript, guideline, and other relevant private evidence. Each reviewer supplies a distinct name, timezone-aware `reviewed_at`, and one `{ "finding_id", "assessment", "rationale" }` for every finding. Assessments are `supported`, `unsupported`, or `unclear`; each rationale must explain the judgment. A third person records final labels for the same IDs under `adjudication`, after both reviews. Reviewer and adjudicator names must differ.

Run `python bench/calibration/labels.py validate /absolute/private/run-1 /absolute/private/labels.json`. It rejects stale hashes, omitted findings, duplicate names, invalid assessments, and labels timed before the run or adjudication timed before either review. The result contains only counts and hashes. Names and timestamps cannot prove independence, and record completeness cannot prove scientific correctness. The current repository has no human-reviewed calibration set, feature provenance, fitted model, or validated precision threshold; do not report a confidence score from these records alone.
