# First editorial decision record contract

This private validator defines inputs for a future categorical decision-prediction benchmark. The skill currently does not emit an editorial prediction, and this directory contains no decision data, accuracy estimate, or probability calibration. Do not use a finding severity as a prediction.

Keep each original manuscript, audit run, prediction, decision letter, outcome label, and case manifest outside Git. A private `cases.json` has `schema_version: 1` and nonempty `cases`. Each case has a unique `case_id` and absolute paths for `run_directory`, `prediction_file`, `outcome_file`, and `decision_letter_file`. The run must pass `validate-run.cjs`.

The prediction JSON contains `schema_version: 1`, `run_manifest_sha256`, the run profile's `target_issn`, `stage: "first_editorial_decision"`, one `category`, timezone-aware `recorded_at`, and a nonempty `predictor_id`. The outcome JSON contains the same schema version, target ISSN and stage, one category, timezone-aware `decision_at` and `labeled_at`, `letter_sha256`, and a nonempty human `labeler`. Categories are `desk_reject`, `reject_after_review`, `major_revision`, `minor_revision`, and `accept`. Do not force an ambiguous or differently staged editorial letter into one of these labels. The prediction must be recorded after run creation and before the first decision; the outcome label must be recorded on or after that decision.

Run `python bench/editor-decisions/validate.py /absolute/private/cases.json`. The command prints only case IDs and input hashes, with `status: "records_structurally_valid"`. It does not score accuracy. File hashes and self-declared timestamps cannot establish that a model made a locked prediction before the editor's decision. A human must verify the original submission, decision stage and category, prediction provenance, and absence of outcome leakage before any scored evaluation is considered. Independent outcome review and a genuinely held-out, multi-journal set are still needed.
