# Review alignment (private, label gated)

`score.py` counts which peer review issues were matched to confirmed review findings in a locally validated audit run. It does not use an LLM judge or infer matches from similar wording. A human reviewer must read the original submitted manuscript and peer report, split the report into distinct issues, mark each issue's scope, and record exact matching finding IDs with a rationale. The scorer checks record hashes and IDs; it cannot verify reviewer identity, whether the report concerns the first submission, or whether a match is scientifically sound.

Keep manuscripts, peer reports, label files, runs, and score outputs outside Git. Do not redistribute peer reports without checking each source's license. A private `cases.json` has `schema_version: 1` and nonempty `cases`, each with `case_id`, absolute `run_directory`, absolute `peer_report_file`, and absolute `labels_file`. Each label JSON has `schema_version: 1`, `peer_report_sha256`, `findings_sha256`, `reviewer`, timezone-aware `reviewed_at`, `manuscript_version: "initial_submission"`, and a nonempty `issues` array. Each issue contains a unique `issue_id`, Boolean `in_scope`, `matched_finding_ids` (zero or more confirmed review finding IDs), and a nonempty `rationale`. Out-of-scope issues must have no matches. Every in-scope issue is included in the denominator. To assess confirmed findings absent from peer issues, add `unmentioned_findings` with one `{ "finding_id": "F-...", "assessment": "supported|unsupported|unclear", "rationale": "..." }` for every such finding. An omitted array leaves that assessment `pending`; a partial array is rejected.

Run `python bench/review-alignment/prepare_label_review.py /absolute/private/run-1 /absolute/private/peer-report.txt /absolute/private/label-packet.json` to create a private worksheet for one validated run. It pins the manuscript, manifest, findings, and report hashes and lists confirmed review finding IDs and classes. It copies no manuscript or peer-report text, cannot verify reviewer identity, and refuses to overwrite an existing packet. A human reviewer must read the first submitted manuscript and original peer report, then copy `label_template` into a separate private labels file and fill in the reviewer, review time, issue records, and adjudications. The empty template deliberately fails the scorer until this work is complete. If the run or peer report changes, generate a fresh packet and labels.

Run `python bench/review-alignment/score.py /absolute/private/cases.json`. It writes `review-alignment-scores.json` beside the manifest without overwriting an existing result. The output contains only counts, recall, IDs, and hashes, without report or manuscript text. An unmentioned system finding is counted separately; it is not a false positive merely because a peer reviewer did not mention it. The optional human assessments are reported as counts, without a precision claim. Local synthetic tests do not establish empirical performance.

After primary labels are complete, run `python bench/review-alignment/audit_labels.py prepare /absolute/private/cases.json /absolute/private/audit-packet.json`. A second human reviewer must inspect the original manuscript, peer report, and primary labels, then copy `audit_template` to a private audit JSON and fill every issue check and every supplied unmentioned-finding check. Each check needs `assessment` (`agree` or `disagree`) and a concrete `rationale`. Run `python bench/review-alignment/audit_labels.py check /absolute/private/cases.json /absolute/private/audit.json`. It rejects changed primary labels, omitted checks, and an auditor name matching a primary reviewer; a disagreement returns `needs_adjudication`. `recorded_agreement` means the record is complete, not that reviewer independence or scientific correctness has been proven. The packet and audit file stay outside Git. Decision prediction accuracy and cross-journal sampling remain open.
