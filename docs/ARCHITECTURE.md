# Architecture

This repository is an Agent Skill. The host agent coordinates the work; local Python tools prepare evidence and Node.js validators check records. There is no hosted service or shared manuscript database. The [skill workflow](../skills/manuscript-audit/SKILL.md) is the operational entry point.

## Data boundary

Manuscripts, extracted text, downloaded guideline pages, model outputs, reviewer records, and reports remain in private directories outside Git. A run contains a `run-manifest.json` that binds the supplied manuscript, supplements, guideline snapshots, skill instructions, and configuration to their hashes. The manifest records the host and model names supplied for that run; it does not prove which model actually ran. Public fixtures contain only short rule quotations and source metadata. The repository uses the [PolyForm Noncommercial License](../LICENSE).

External discovery requests use an explicit, nonconfidential topic phrase. Sending selected reference DOIs to OpenAlex or manuscript identifiers to Crossref or arXiv requires the author's approval. An unpublished manuscript is never sent to these discovery APIs as a search query.

Public metadata and guideline GETs use `http_client.py` for caller-specific response limits, HTTPS same-host redirects, and bounded retries of temporary provider failures. Cached journal profiles are reused only from an explicitly selected private run or private run root; this client does not silently reuse old API or guideline responses.

## Workflow

1. **Discover candidates.** `discover_journals.py` groups matching OpenAlex articles by primary journal, enriches journal identity and ISSNs, and ranks an incomplete shortlist using a volume-normalized topic share. Optional DOAJ subject results and a separate, approved citation record add evidence by ISSN or OpenAlex source ID. Manually selected web results pass an OpenAlex, DOAJ, or Crossref ISSN gate before entering the shortlist; their URLs remain unverified pointers. Counts and strategy overlap explain why a journal appears; they do not estimate acceptance probability. The author selects the target after checking scope and submission status.
2. **Capture official instructions.** `capture_candidate_guidelines.py` starts from a selected private discovery record. For a DOAJ pointer it rechecks the current DOAJ journal ID, ISSN, and exact author-instruction link, then verifies its host against the current DOAJ journal homepage or, when different, the current OpenAlex journal or publisher homepage. A narrow Springer Nature adapter derives a guideline URL only from a current, ISSN-matched OpenAlex `springer.com/journal/<id>` homepage. An IEEE Access adapter requires its exact current journal and publisher identity plus its indexed homepage before selecting the official submission page. Without a usable indexed link or adapter, it accepts one explicit author-guide link on the current ISSN-matched OpenAlex homepage, or the current DOAJ homepage for a DOAJ-only journal, only when the link stays on the same HTTPS host. HTTP homepage pointers are upgraded to HTTPS without an HTTP request. The homepage response hash is recorded privately; its raw content is discarded. An operator-supplied URL needs a current OpenAlex identity or, for a DOAJ-only journal, the current DOAJ homepage host. Guideline redirects are host-locked; the Springer adapter allows only the exact journal page and publisher identity-cookie route. `fetch_guidelines.py` stores extracted page text, its URL, retrieval time, and hashes privately. A successful capture is still pending human page review; an inaccessible or unmatched source remains unresolved.
3. **Build a journal profile.** Two fresh profile builders independently read the same private guideline snapshot and use canonical rule IDs. `compare-profiles.cjs` checks their structure, source identity, quotes, and agreement. `adjudicate-profiles.cjs` requires an explicit, source-based resolution for each disagreement. A partial profile may retain disputed rules as `needs_validation`; those rules cannot support confirmed findings. The 20 Computer Science profiles in [`journal-profiles/`](../journal-profiles/README.md) are dated fixtures, not an exhaustive catalog.
4. **Prepare and check the manuscript.** `prepare_run.py` creates the private run and manifest, retaining directly submitted filenames separately from normalized internal paths. The coverage ledger assigns one unit per applicable verified rule and optional section/review-class pairs. Deterministic tools measure supported Markdown counts and headings. Statistical screens, identifier lookups, and manually selected bibliography-to-registry comparisons produce leads that need context checks. Crossref `updated-by` entries are preserved as provisional update signals, not a final retraction verdict; missing entries do not prove no retraction. A covered unit requires a separate, fingerprinted check record. An absence claim must search every supplied file.
5. **Review findings.** The hunter records a candidate with exact guideline or manuscript evidence. A confirmed reference finding binds a selected bibliography span to the private Crossref comparison record; a registry mismatch alone remains provisional. `prepare-review-packet.cjs` validates the current run and creates a private defense packet without hunter reasoning or proposed severity. After defense, it creates a verifier packet with the proposed final record and defense decision but without either reviewer's rationale. A fresh defense invocation tests the strongest counterevidence; a separate record verifier checks the final claim and evidence again. Distinct actor IDs and hashes are required in [`agent-record.schema.json`](../skills/manuscript-audit/schemas/agent-record.schema.json). New role records can also pin each invocation's host and model against the run manifest; legacy records without those fields cannot support model-combination claims. The host must enforce actual independence: validators cannot prove that separate files came from separate reviewers.
6. **Validate and report.** `validate-run.cjs` checks the manifest, profile, source hashes, coverage, findings, and review records together. `render-report.cjs` writes private `REPORT.md`, `NEEDS-VALIDATION.md`, and `REVISION-PLAN.md`. The revision plan uses confirmed findings only. `compare-runs.cjs` records changes between runs without treating a missing finding as proof of resolution.

## Evidence contracts

The [run manifest](../skills/manuscript-audit/schemas/run-manifest.schema.json), [journal profile](../skills/manuscript-audit/schemas/journal-profile.schema.json), [coverage ledger](../skills/manuscript-audit/schemas/coverage-ledger.schema.json), and [findings](../skills/manuscript-audit/schemas/findings.schema.json) are separate contracts. A finding identifies its target ISSN, category, verdict, claim, evidence, and provenance. Only confirmed findings have severity. Missing source text, ambiguous rules, incomplete coverage, stale hashes, or unavailable independent review must remain visible as unresolved work.

Local validation establishes record consistency and reproducible quotations, not the scientific correctness of a criticism or the authority of a live page. The author and independent reviewer must inspect those judgments.

## Journal coverage and on-demand profiling

**Decision:** Present an evidence-backed journal shortlist, not a complete catalog or acceptance ranking. Combine grouped OpenAlex counts, approved citation venues, optional DOAJ subject results, and optional web leads that pass an ISSN registry check. Preserve each discovery signal and normalize topic counts by the journal's recorded publication volume. A registry match confirms journal identity only; it does not verify a web result, editorial scope, or submission status.

The 20 Computer Science profiles are starting fixtures. For a selected journal, obtain current instructions from its verified journal or publisher domain, keep the page snapshot outside Git, and have two independent builders extract and quote-check rules. `prepare_cached_run.py` can find a reconciled profile by ISSN in a private run root or reuse an explicitly selected run within a chosen TTL. It accepts exact two-draft agreement or a hash-bound, replayable adjudication of differences, and refuses partial profiles or ambiguous candidates. `--verify-live` also requires every current source URL and extracted text to match before reuse. Without that flag, hash and age checks do not establish that the live page is unchanged. The intended extension is publisher-level rules with journal-specific overrides, each retaining its own source and quotation. If an official rule cannot be verified, mark that part of the profile as unresolved and continue only with checks that have evidence. Never infer missing journal rules from model memory.

Measure candidate coverage across fields with strategy-by-strategy hit-at-k tests, and measure verified profile extraction by publisher. These measurements require independently checked cases; the current fixture set and structural benchmark cannot establish either rate.

## Current limits

- Discovery reads one OpenAlex journal-group page by default. With a private OpenAlex API key it can read two to five cursor pages; anonymous requests cannot page past the first. The private record marks a one-page scan incomplete and states whether a cursor scan exhausted the groups. Only the first optional DOAJ subject page is used. Citation discovery uses manually selected reference DOIs and the first citing-journal group page. Automatic web search, special-issue matching, adapters for other publishers, inherited publisher profiles, and automatic cache refresh are not implemented. Cache lookup searches a supplied private run root; it does not discover caches elsewhere on the machine.
- The supported deterministic profile metrics are abstract words, main-text words, keyword count, and an exact Markdown heading count. PDF extraction does not establish reliable structure for these measurements. LaTeX conversion requires comparing Markdown with the rendered manuscript before those measurements are trusted. Other statistical and reference tools are provisional screens.
- The [compliance mutation benchmark](../bench/compliance-mutations/README.md) has a limited structural check. New cases require a private, hash-bound scoring-scope decision for every applicable rule; an unfilled human worksheet exposes proposed inclusions and exclusions with their source evidence. Mutation output discloses flags on rules other than the injected target. Its human-label gate requires adjudicated labels for every scored rule in both control and mutation before reporting an off-target false-positive rate. Broad performance estimates await more independent cases and human-reviewed scope, control, and mutation labels. No result from the current suite establishes general manuscript-compliance performance.
