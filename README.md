# Manuscript Audit Skill

An early-stage skill for checking a manuscript against a selected journal's guidelines. See the [architecture](docs/ARCHITECTURE.md) for the evidence flow and current limits.

The current implementation provides [skill instructions](skills/manuscript-audit/SKILL.md), [review role contracts](skills/manuscript-audit/roles/REVIEW-ROLES.md), JSON contracts, local validators, private report rendering, and a [run preparation tool](skills/manuscript-audit/tools/prepare_run.py) for UTF-8 text or Markdown. It can fetch public HTML or plain-text guideline pages and convert DOCX, standalone LaTeX, or text-based PDF content locally. Private run files are created outside any Git checkout.

The five optional host agents in `.claude/agents/` and `.codex/agents/` are generated from `skills/manuscript-audit/roles/roles.yaml`. When the skill is installed into another project, run `python <installed-skill>/roles/gen_agents.py --write --output-root <project-root>` to create the same project agents; the generator refuses to overwrite changed files unless `--force` is supplied. Claude agents have only the `Read` tool. Codex agents inherit the parent's sandbox and can still use its shell; run them under a parent session with the intended network and file permissions. Neither host agent definition proves that invocations are independent. The host records actual invocation IDs and keeps the review packets separate.

For a DOCX manuscript, run `python skills/manuscript-audit/tools/convert_docx.py --input /path/to/paper.docx`. Inspect the private `extraction.json` warnings and `manuscript.md` before preparing the run. Pass both files to `prepare_run.py` with `--manuscript <manuscript.md> --extraction-record <extraction.json>` to retain the original DOCX hash in the private run. Tables are flattened; figures, notes, and some Word fields require separate inspection. Documents with tracked changes, content controls, custom XML wrappers, nested tables, or text marked hidden, zero-sized, or white are rejected for manual resolution before extraction. The visibility check includes applied Word styles but is conservative; compare the result with the rendered document and inspect any formatting it cannot establish.

For a standalone UTF-8 LaTeX manuscript, install [Pandoc](https://pandoc.org/) and run `python skills/manuscript-audit/tools/convert_tex.py --input /path/to/paper.tex`. Compare the private `manuscript.md` against the rendered manuscript, then pass it and the private `extraction.json` to `prepare_run.py` as above. The converter rejects external source inclusions; consolidate multifile projects before conversion. Bibliographies, figures, custom macros, equations, and tables require manual inspection. The original `.tex` is not copied into the private run; its SHA-256 is retained in the private extraction record.

Before two independent profile drafts have been reconciled, `python skills/manuscript-audit/tools/check_deterministic.py <private-run> --article-type <type> --profile-draft profile-a.json --no-write` can screen a source-validated draft without creating an official check report. The JSON result identifies itself as provisional and pins the draft hash. A measured heading or word count is a review lead, not an agreed profile or a human control label.

For a text-based PDF, install the optional dependency with `python -m pip install -r requirements-pdf.txt`, then run `python skills/manuscript-audit/tools/convert_pdf.py --input /path/to/paper.pdf`. Inspect every page of the original PDF against the private `manuscript.txt` before preparing a run, and pass `--extraction-record <extraction.json>` alongside `--manuscript <manuscript.txt>`. The extractor marks page boundaries, flags pages with no text, and rejects PDFs with no extractable text. It does not perform OCR or establish reliable heading, table, equation, or figure structure; Markdown-only measurements remain unresolved for PDF text.

After `prepare_run.py`, run `python skills/manuscript-audit/tools/build_manuscript_profile.py <private-run>`. It validates the pinned manuscript, supplements, sources, and extraction record before writing a private `manuscript-profile.json` without overwriting an earlier one. For Markdown, the profile records observed ATX headings with physical line IDs and inclusive section ends, a possible References/Bibliography span, literal figure/table marker lines, rough word tokens, and DOI mentions. These are mapping aids, not verified figure counts, reference entries, journal word counts, or Crossref checks. Plain-text PDF runs retain page marker positions but leave section and reference structure unresolved. Inspect the original document before relying on any mapped content.

The [private parsing benchmark harness](bench/parsing/README.md) compares converted DOCX and LaTeX section headings and reference entries with human labels from the original document. It pins source and extraction hashes and reports counts without publishing text. The repository includes invented integration tests, not a human-labeled parsing result.

If a journal has not been chosen, use an explicit, nonconfidential topic phrase to discover candidates from [OpenAlex](https://help.openalex.org/api/llm-quick-reference/) metadata:

```sh
python skills/manuscript-audit/tools/discover_journals.py --query "synthetic topic" --field-id 17 --published-after 2024-01-01
```

For a known field, add its OpenAlex field ID, such as `--field-id 17` for Computer Science. `--published-after` limits matching articles to a chosen publication window; it does not prove that a journal is still accepting submissions. By default, discovery groups matching articles by their primary journal on one page, checks source type and ISSN-L against OpenAlex source records, and writes up to 50 candidates to a private `candidates.json` under `~/manuscript-audit/discovery/discovery-N/`. With `OPENALEX_API_KEY` set privately, use `--group-pages 2` through `5` for bounded cursor paging; [OpenAlex requires a key past the first cursor page](https://help.openalex.org/api/authentication/). Set `--limit` to change the candidate cap. The private output records each group and source response hash, page count, and whether the cursor was exhausted; a single non-cursor page is conservatively marked incomplete. It contains source metadata and aggregate counts, not article text. Topic share divides matching articles by the source's all-time work count, so it is an approximate discovery signal, not a publication probability. The bounded page scan and OpenAlex coverage remain incomplete. The author selects the target journal after checking its scope and current submission status. A candidate's homepage URL is metadata, not a verified guideline source; fetch and verify the journal's official author instructions before building a profile. If official instructions cannot be verified, keep the profile partial. The earlier work-sample method remains available with `--strategy sample`.

Add `--doaj-subject "Computer Science"` when a separate, nonconfidential [DOAJ](https://doaj.org/docs/widgets/) subject phrase is available. This searches DOAJ's journal classifications and considers its first 50 results. Matching ISSNs add a second discovery source to an OpenAlex candidate; a limited number of DOAJ-only journals may also appear without OpenAlex work counts. The output records which source found each candidate and hashes both responses. DOAJ author-instruction links are pointers to review, not verified rule text: confirm the current official journal or publisher domain and page content before fetching guidelines or creating a profile. Neither index is exhaustive, and this shortlist is not an editorial suitability or acceptance ranking.

Citation venues are a separate, optional signal. Manually select actual reference DOIs into a private JSON file outside Git, such as `{"schema_version":1,"dois":["10.1038/nature14539"]}`, then run `python skills/manuscript-audit/tools/discover_citation_journals.py --references /private/references.json --allow-network`. This sends only those DOI values to OpenAlex, groups the journals of resolved references and the first page of journals publishing works that cite them, and writes a private `citation-candidates.json`. Pass that file to `discover_journals.py --citation-record /private/citation-candidates.json` to add citation-graph evidence to matching journals and include some citation-only candidates. A DOI inventory contains mentions, not a verified reference list, so do not pass it directly. The counts omit unindexed works and later group pages. Citation frequency does not establish topic fit or acceptance likelihood.

Optional web results enter through an ISSN gate. Save at most 20 manually selected, nonconfidential results outside Git as `{"schema_version":1,"candidates":[{"issn":"2475-9066","result_url":"https://joss.theoj.org/about"}]}`, then add `--web-candidates /private/web.json` to `discover_journals.py`. The tool sends only the ISSNs to OpenAlex, DOAJ, or Crossref and includes a candidate only after a unique journal record confirms its ISSN. The web URL is retained as an **unverified pointer** and is never fetched or used as the journal homepage; registry identity does not establish scope, legitimacy of the web page, or acceptance probability. Rejected ISSNs and response hashes remain in the private discovery record. Automatic web search and special-issue matching are not implemented.

For a selected DOAJ-linked candidate, run `python skills/manuscript-audit/tools/capture_candidate_guidelines.py --discovery-record /private/candidates.json --issn 2666-6510 --allow-network`. The tool checks the current DOAJ record for a unique matching journal ID, ISSN, and unchanged author-instruction link. It accepts the link on the current DOAJ journal homepage host; a different host requires a matching current OpenAlex journal or publisher homepage, or the exact Springer Nature journal URL pattern derived from the current OpenAlex homepage. DOAJ-only candidates can use their current journal host. Redirects outside the verified host are blocked; the Springer Nature adapter permits only its checked journal page and its publisher identity-cookie route. The private `source-locator.json` records the domain basis and registry response hashes. A `captured_pending_review` result includes a hashed `source.json` and extracted `guideline.txt`; inspect the current official page and extracted text before building any rules. A `needs_manual_verification` result requires an independently verified official journal or publisher page through `fetch_guidelines.py`. This locator does not create a journal profile or treat an indexed URL as proof that every instruction is current.

For a candidate without a usable DOAJ author-instruction link, the Springer Nature adapter can locate `submission-guidelines` when the current matching OpenAlex journal homepage has the exact `springer.com/journal/<id>` pattern. An IEEE Access adapter uses only its exact ISSN, OpenAlex source and publisher identities, and indexed journal homepage to select the official submission-guidelines page. Otherwise, the tool checks the current ISSN-matched OpenAlex homepage, or the current DOAJ homepage for a DOAJ-only candidate, for one explicit same-host author-guide link. An HTTP homepage pointer is upgraded to HTTPS on the same host, without an HTTP request. It records the fetched homepage URL and response hash in the private locator; the raw homepage is not saved. Missing, ambiguous, or external links remain `needs_manual_verification`. An operator can supply an independently reviewed URL with `--guideline-url https://journal.example/authors`. The tool requires its host to match the current journal homepage, linked publisher homepage, or an exact supported adapter pattern; for a DOAJ-only candidate, it must match the current DOAJ journal homepage. A captured guideline still needs live-page review before profile building.

**Journal coverage decision:** Discovery is an evidence-backed candidate shortlist, not an exhaustive list or acceptance ranking. Bounded OpenAlex group pages, optional DOAJ subject results, and an optional private citation record are separate signals; the page limits and source metadata constrain coverage. The 20 public profiles are dated fixtures. For a selected journal, current official instructions must be captured privately, independently read, and quote-checked before any rule can support a finding. Prior-run profile reuse has an age and hash gate. Springer Nature and IEEE Access have narrow adapters, and other journals can use an explicit same-host homepage link; other publisher adapters, automatic web discovery, profile inheritance, and automatic cache refresh remain planned. Missing instructions or disputed rules remain `needs_validation`.

To fetch a public guideline page and prepare a run, inspect the extracted text before using it:

```sh
python skills/manuscript-audit/tools/fetch_guidelines.py --url https://example.org/authors
python skills/manuscript-audit/tools/prepare_run.py --manuscript /path/to/paper.md --source-record /path/to/manuscript-audit/sources/source-1/source.json
```

Repeat `--source-record` for every relevant guideline page. Each page receives its own source ID, URL, retrieval time, and content hash in the private run; no cached page is committed to the repository.

For manually verified guideline text, supply the actual guideline URL and its known retrieval time:

```sh
python skills/manuscript-audit/tools/prepare_run.py --manuscript /path/to/paper.md --guideline-text /path/to/guideline.txt --guideline-url https://example.org/authors --retrieved-at 2026-10-19T09:00:00Z
node skills/manuscript-audit/validators/validate-run-manifest.cjs /path/to/manuscript-audit/paper/run-1
```

The private manifest retains each directly supplied file's `submitted_filename` while using stable internal paths such as `manuscript.md`. Filename-sensitive rules must use the submitted name; a normalized internal path is not evidence of the original filename. A converted DOCX, PDF, or TeX file has no verified submitted Markdown filename, so filename-sensitive checks remain unresolved until the source filename is established separately. Filename changes alter the coverage fingerprint.

After adding `journal-profile.json`, `coverage-ledger.json`, `findings.json`, and the referenced agent records to that run, check the record and local evidence chain with `node skills/manuscript-audit/validators/validate-run.cjs <run-directory>`. A confirmed compliance finding requires a covered unit for its rule, and every compliance unit is fingerprinted against the full supplied corpus. Use `--supplementary <file.md|file.txt|file.bib>` during preparation for each supplied text or bibliography supplement; an absence claim must search all of them. The validator checks records and hashes; it cannot prove that reviewers worked independently.

For a new journal profile, save two separately prepared drafts as `profile-a.json` and `profile-b.json` in the private run. Each builder can run `node skills/manuscript-audit/validators/validate-profile-draft.cjs <run-directory> profile-a.json` (or `profile-b.json`) to check the run manifest, source hashes, quoted text, and source identity before comparison. This read-only check does not establish independent agreement or create a final profile. `node skills/manuscript-audit/validators/compare-profiles.cjs <run-directory> profile-a.json profile-b.json --promote` checks both against the cached source, writes a private comparison record, and creates `journal-profile.json` only when all fields agree. If the journal identity and source set agree but individual rules differ, `--promote-partial` creates a private working profile that keeps disputed and one-sided rules marked `needs_validation`. It omits disputed scope or AI-policy text. Such a profile is incomplete: resolve each disagreement against the guideline before calling the journal profile verified. Matching text alone cannot prove the two readings were independent.

To reuse a reconciled profile for another manuscript without downloading its guideline pages again, run `python skills/manuscript-audit/tools/prepare_cached_run.py --source-run /private/previous/run-1 --manuscript /private/new-paper.md --ttl-days 30`. Alternatively, use `--cache-root /private/previous --issn 2475-9066` to find an eligible run in that private root. The tool refuses to choose between different fresh profiles for the same ISSN. It creates a new private run with the exact source snapshots and profile, requires either an agreed two-draft comparison or a source-backed adjudication record, checks all source and profile hashes, pins the comparison and optional adjudication hashes in `profile-reuse.json`, and rejects any source older than the chosen TTL. Add `--verify-live` to fetch every source URL and require its current extracted text and URL to match the cached snapshot before any new run is created. A mismatch requires a newly reviewed profile. Without this flag, compare the selected ISSN and current official instructions yourself: a recent snapshot can still be superseded, and matching drafts do not prove independent reading. Partial profiles require fresh review instead of this reuse path.

The [20 dated Computer Science profile fixtures](journal-profiles/README.md) show the resulting rule format; retrieve and hash-check each profile's cited official pages before applying its rules to a manuscript.

To resolve differences, save `decisions.json` privately with `{"schema_version":1,"resolutions":{"rules.example":{"choice":"first","reason":"The official wording supports this narrower rule."}}}`. Include exactly one reasoned decision for every field in the comparison record. Choices are `first`, `second`, or `omit`; set `"status":"needs_validation"` when the selected rule cannot yet be checked. Run `node skills/manuscript-audit/validators/adjudicate-profiles.cjs <run-directory> profile-a.json profile-b.json decisions.json`. The tool checks the selected profile and its source quotes, rejects journal identity differences and upgrades of unresolved rules, then creates the private `journal-profile.json` and a hash-bound adjudication record. Cache reuse and human-reviewed benchmark scoring replay the decisions against both original drafts; changes to a draft, decision, or profile invalidate that authorization. A source-verified rule may still need evidence outside the supplied manuscript. New benchmark studies use a separate private scoring-scope record for that distinction.

For a journal profile with Markdown abstract, main-text word, keyword-count, or required-heading rules, `python skills/manuscript-audit/tools/check_deterministic.py <run-directory> --article-type original_research --main-start Introduction --main-end References` records provisional measurements in the private run. Keywords can be under their own heading or on the final plain-text line of the abstract; that line is excluded from the abstract word count. A required heading uses `{"metric":"heading_count","heading":"Data Availability","op":">=","value":1}` in the journal profile. Unclear section boundaries or unsupported formatting stay unresolved; heading counts from PDF text are not inferred.

For explicitly labeled, same-line two-sided z statistics and p values, `python skills/manuscript-audit/tools/check_z_p.py <run-directory>` writes private `z-checks.json`. It compares the normal-tail probability while allowing for the printed precision of z and equality p values.

For explicit same-line two-sided `t(df)` and Pearson `r(df)` pairs, or `F(df1, df2)` and `χ²(df)` pairs, install the optional dependency with `python -m pip install -r requirements-stats.txt` and run `python skills/manuscript-audit/tools/check_stats.py <run-directory>`. The private `statistical-checks.json` compares the printed p value with SciPy distribution tails over the statistic's rounding interval. It skips one-sided and correction-labeled lines, unrecognized formats, and tests without the required degrees of freedom. `needs_review` and its proposed severity are screening leads only: inspect the original manuscript, test definition, tail, corrections, and assumptions before making a finding.

For a mean of one integer-valued item per observation, supply the sample size and scale bounds in a private `cases.json`, then run `python skills/manuscript-audit/tools/check_grim.py <run-directory> --cases /path/to/cases.json`. A case has `case_id`, `path`, `line_id`, `reported_mean` as a string, `sample_size`, `scale_min`, and `scale_max`; for example, `{"case_id":"M1","path":"manuscript.md","line_id":"L42","reported_mean":"2.34","sample_size":13,"scale_min":1,"scale_max":5}`. The tool checks that the mean appears on the cited line and whether any integer total could round to it. It cannot verify the sample size, scale, missing data, or how composite scores were calculated; inspect those assumptions before treating `needs_review` as a finding.

To inventory DOI mentions in the supplied manuscript and text supplements, run `python skills/manuscript-audit/tools/list_dois.py <run-directory>`. It writes a private `doi-inventory.json` with file and line references. DOI mentions do not establish that the reference list is complete or that a citation is correct.

For labeled arXiv identifiers, run `python skills/manuscript-audit/tools/list_arxiv_ids.py <run-directory>`. It writes a separate private `arxiv-inventory.json` with file and line references. This catches modern and legacy `arXiv:` IDs but does not look them up or infer which references lack an identifier.

To check those IDs against the [arXiv API](https://info.arxiv.org/help/api/user-manual.html), run `python skills/manuscript-audit/tools/check_arxiv_ids.py <run-directory> --allow-network`. This sends the IDs to arXiv and saves limited registry metadata in a private `arxiv-metadata.json`; it does not store abstracts or full text. The tool batches requests and follows [arXiv's three-second API interval](https://info.arxiv.org/help/api/tou.html). A missing record still needs manual review.

To check those DOI values against the [Crossref REST API](https://www.crossref.org/documentation/retrieve-metadata/rest-api/), run `python skills/manuscript-audit/tools/check_dois.py <run-directory> --allow-network`. This sends DOI values to Crossref, which may reveal the manuscript's reference topics. You may set `CROSSREF_CONTACT_EMAIL` privately to add Crossref's recommended `mailto` parameter to DOI lookups and Crossref journal identity checks; the address is sent to Crossref but is not saved in the repository or run results. OpenAlex uses `OPENALEX_API_KEY` instead of an email polite pool. The private `doi-metadata.json` records registry status, response hashes, limited title, year, and first-author metadata, plus bounded [post-publication update signals](https://www.crossref.org/documentation/retrieve-metadata/retraction-watch/) from the cited work's `updated-by` field. A retraction, correction, or other update signal needs direct notice and publication-record review. No reported update does not prove the work has never been retracted; a Crossref miss does not prove a DOI is invalid; and a registry match does not verify the citation details. No manuscript text or cached PDF is sent.

Successful Crossref responses are also saved under the private run's `sources/crossref/` directory by response hash. `check_reference_metadata.py` replays the saved response before using its selected fields, and a confirmed reference finding's defense and verifier packets include that snapshot. Earlier DOI metadata without a saved response cannot support a new reference comparison; prepare a fresh private run and obtain author approval before repeating network lookups. Never add these raw responses to Git.

For an actual bibliography entry, select its physical line span in a private `reference-cases.json`, such as `{"schema_version":1,"references":[{"doi":"10.1234/alpha","path":"manuscript.md","start_line":42,"end_line":43,"stated_title":"Example title","stated_year":2024,"first_author_family":"Example"}]}`. Run `python skills/manuscript-audit/tools/check_reference_metadata.py <run-directory> --cases /private/reference-cases.json`. The tool requires the DOI, stated title, year, and optional first-author name to occur in that 1–8 line span, then compares them with the saved Crossref fields and update signals. It writes private `reference-metadata-checks.json` with `metadata_consistent`, `needs_review`, `metadata_incomplete`, or `registry_unavailable` statuses. A mismatch or reported post-publication update is a provisional lead: editions, online versus print dates, incomplete registry deposits, citation formatting, correction scope, and any later reinstatement require manual inspection. An inventory of DOI mentions alone is not a bibliography.

A confirmed reference finding needs a manuscript quote from the selected reference span, a `reference_metadata` evidence item identifying the DOI and result index in `reference-metadata-checks.json`, and that file's SHA-256 as `checks_sha256`. The full run gate checks the private file, its underlying DOI inventory and Crossref metadata hashes, and the current manuscript span. A `needs_review` registry comparison is only a lead; independent defense and record verification still have to establish the actual criticism. Confirmed review findings similarly require a manuscript quote and a covered review unit for their review class.

Create a pending compliance ledger from the selected article type with `python skills/manuscript-audit/tools/build_coverage.py <run-directory> --article-type original_research`. The tool refuses to overwrite an existing ledger; each unit carries a fingerprint of the supplied manuscript files.

For one pending verified compliance unit, run `node skills/manuscript-audit/validators/prepare-compliance-packet.cjs <run-directory> U-1 original_research` and give only the resulting private JSON packet to a fresh hunter invocation. The packet contains the assigned rule, its pinned source, and every supplied manuscript file; it excludes existing findings and reviewer rationales. The command refuses unresolved rules and changed inputs. Generating a packet does not cover the unit or create a finding: record the actual check and any candidate separately.

For a controlled compliance benchmark, set `--data-freeze YYYY-MM-DD` when preparing each private run. The [compliance mutation scorer](bench/compliance-mutations/README.md) checks paired controls and mutations, validates final records, and reports recall and false-positive rates before and after independent validation. New schema-version-4 runs also measure unsupported raw evidence quotes against pinned private inputs. The [limited heading suite](bench/compliance-mutations/heading-suite-results.json) records seven controlled mutations on one CC BY paper; its earlier format has no quote-audit rate. It does not ship manuscript text or estimate full manuscript-compliance performance.

After actually checking a unit, run `node skills/manuscript-audit/validators/hash-coverage.cjs <run-directory> U-1` and save a private check record under `agents/` using `schemas/coverage-check.schema.json`. Record the unit ID, `decision: "checked"`, the actual invocation ID as `actor_id`, the printed `subject_sha256`, and a concrete `rationale`. Set that unit to `covered` and add the record path to `checked_by`. The full run gate rejects missing, mismatched, or stale check records; a file path alone does not establish coverage.

For explicit review coverage, add `--review-section Methods --review-class statistics` (repeat either flag for more sections or review lenses). This creates pending section/class pairs. The validator marks their fingerprints stale when supplied manuscript files change.

For independent finding review, first save a candidate in `findings.json` as `needs_validation` with a hunter record and no other provenance paths. Run `node skills/manuscript-audit/validators/prepare-review-packet.cjs <run-directory> F-1 defense` and give only the generated private JSON packet to a fresh defense reviewer. After recording its decision, set the proposed final verdict and add the defense record plus a planned `agents/<name>.json` verifier path. Run the command again with `record_verifier` for a fresh verifier. The packets contain the exact supplied text and source snapshots, so keep them outside Git and obtain the author's approval before sending one to another provider. They omit earlier reviewers' rationales; the verifier packet includes only the defense decision. For each new role record, include the actual invocation `host` and `model` together and list that model in the private run manifest; older records without these fields cannot support model-combination claims. The host writes the verifier record and then runs `validate-run.cjs` before rendering. Packet checks and distinct actor IDs support separation, but the host must enforce fresh, independent invocations.

Once the profile, ledger, findings, and agent records pass `validate-run.cjs`, generate private summaries with `node skills/manuscript-audit/validators/render-report.cjs <run-directory>`. `REPORT.md` lists confirmed records, names every pending or stale coverage unit, and quotes a verified journal AI policy when one is recorded. `NEEDS-VALIDATION.md` includes each unresolved finding's evidence, open coverage units, and journal rules needing validation so the remaining review is identifiable. `REVISION-PLAN.md` orders only confirmed findings by recorded severity and repeats their recorded suggested changes.

For a revised manuscript, prepare and validate a new run, then use `node skills/manuscript-audit/validators/compare-runs.cjs <previous-run> <current-run>`. The private comparison lists changed records and coverage states without treating a missing finding as resolved. Reviewer records from the prior run become stale when the manuscript files or guideline sources change.

## Public-paper example

The [ALICE Collaboration paper arXiv:2404.07542v2](https://arxiv.org/abs/2404.07542) is available under [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/). A private demonstration run compared its extracted PDF text with the [PLOS ONE submission guidelines](https://journals.plos.org/plosone/s/submission-guidelines) as a hypothetical target. The guideline page was retrieved on 2026-10-19 at 10:44:44 UTC; its locally extracted text has SHA-256 `9b001b7db59c1dce0434004ac044f220832cbda192eb900ed91f83c33817303f`. The original PDF and extracted text are not in this repository.

The validated local records produced this report summary:

```text
Journal: PLOS ONE
Coverage: 0 covered, 1 pending, 0 stale
Confirmed findings: none
Needs validation: F-1 — A short title is not apparent in the extracted manuscript text.
```

F-1 is an unresolved search result. The submission form, supporting files, and PDF reading order were not checked, so the example does not claim the paper violates a journal rule. The report does not predict an editorial decision.
